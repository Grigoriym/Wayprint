# Frictions

Tooling friction hit during work, newest last. One line each. Promoted or fixed
entries get deleted — see /finalize.

- M5.2 verify: `adb shell content query --uri content://media/external/file --where "_data='...'"` threw `IllegalArgumentException: Invalid token storage` regardless of quoting — worked around with `--projection _id:_data` (no `--where`) piped to `grep`.
- M5.2 verify: `am start -a android.intent.action.SEND --grant-read-uri-permission --eu ... content://media/external/file/<id>` failed with "has no access to" — `adb shell am`'s calling identity (shell) can't forward a grant on a MediaStore row it doesn't itself hold under API 36's scoped media permissions; worked around by driving the real Files-app Share/Open-with UI instead of synthesizing the intent.
- M5.4 verify: `adb shell content query --uri content://media/external/images/media --projection col1,col2,col3` (comma-separated) threw `IllegalArgumentException: Invalid column col1,col2,col3` — worked around by omitting `--projection` entirely and grepping the full row output instead.
- M6.3: no local tool could validate `.github/workflows/ci.yml`'s YAML (`actionlint`/`yamllint` absent, `pip install pyyaml` refused under PEP 668 without `--break-system-packages`) — settled for hand-inspection instead of a real syntax check.
- Top-bar UI polish verify: `uiautomator dump` of DocumentsUI's file-picker list omitted the last (partially below-fold) row's text node (`fixture.gpx`) twice in a row — a screenshot taken at the same moment showed it fine. A third dump captured it. Retried the dump rather than assuming the row wasn't there/was misnamed.
- M6.3 verify: `ci.yml`'s `paths-ignore: docs/**`/`**.md` silently skipped both a docs-only push and a follow-up `git commit --allow-empty` (zero changed files also gets treated as "nothing outside the ignore list") — no run was queued for either, with no error. Worked around by adding a `workflow_dispatch:` trigger and pushing that real (non-ignored) file change instead.
- M7.1 verify: `./gradlew :feature:wayprint:domain:test` (as CHECKLIST.md's Verify line literally reads) failed with "task 'test' is ambiguous" — this is an Android-only KMP module, so the real task is `testAndroidHostTest`.
- M8 step-break-down: an `Edit` on `IMPLEMENTATION_PLAN.md` failed with "old_string not found" against a multi-line `old_string` copied verbatim from a prior `Read` of the same lines (confirmed identical byte-for-byte, including the `§` characters, on a second attempt) — retrying the exact same call with no changes succeeded. Cause not identified.
- M9.5 verify: detekt's compose-rules `ParameterNaming` rejected an `onImportHandled`/`onImportConsumed` composable lambda param as past-tense twice in a row — the rule flags any `on`-prefixed lambda param name, not just the `-ed` suffix a first guess avoided; worked around by dropping the `on` prefix entirely (`clearPendingImport`).
- M11.2 verify: ktlint flip-flopped on a multi-line chained-call private function — block body got `function-expression-body` (wants `=`), and `=` with the chain's first call on its own line got `function-signature` (wants first line on the same line as the signature); only `= generateSequence(...)` on the signature line itself, chain continuing indented below, satisfied both.
- M11.4: `Icons.Filled.CallMerge` failed to compile ("Unresolved reference") — this project only depends on `material-icons-core`, which exposes a small curated subset of Material icon names; most named icons (including `CallMerge`) live only in `material-icons-extended`, not pulled in here. Worked around by using `Icons.Filled.Check` (a core-set icon) instead of adding the extended dependency for one icon.
- M12.4 verify: `adb shell run-as com.grappim.wayprint.debug cp /sdcard/<file> files/...` failed with `cp: bad '/sdcard/<file>': Permission denied` (scoped storage blocks the app-UID process from reading an adb-pushed sdcard file even via `run-as`) — worked around by piping the local file's content through `adb shell` stdin instead: `cat local.json | adb shell "run-as <pkg> sh -c 'cat > files/.../metadata.json'"`.
- M13.1 verify: tapped the Save button using coordinates read off a screenshot without the display→device-pixel scale factor applied (the exact mistake the `emulator-testing` skill already warns about) — missed entirely, no MediaStore row appeared; re-derived the coordinate from `uiautomator dump`'s real-pixel `bounds` instead and it worked on the next tap.
